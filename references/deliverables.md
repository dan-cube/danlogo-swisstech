# 体系、场景、提案与交付

第 6–8 阶段和最后的交付。每一节先讲**怎么做**，再给清单。

**审美按本风格**：这一章只规定做什么、按什么顺序、查什么。体系、场景、提案**长什么样**——辅助图形、版式、字、颜色比例、图片、动态的性格、场景的材料、提案的版面与语气——写在本风格的 `style-extension.md`，每个环节都按它来。标志之后的每一样东西都要和标志出自同一种审美，整套设计才有说服力。

## 6 体系：怎么做与清单

**先定规则，再出文件。** 体系的每一条都写成可以量的规则（以基准尺寸表示），再由代码批量导出，改一个数全部跟着变。

**怎么做**：
1. **组合**：先做竖式和横式，再做单行与纯图形。图与字的距离、字高与图高的比例都从基准推出；不同组合之间，这个比例保持一致。
2. **留白与最小尺寸要实测**：把标志缩到候选的最小尺寸，渲染后亲眼看（屏幕 px、印刷 mm 各一个）。在这个尺寸看不清时，启用小尺寸版，而不是放宽规则。
3. **色彩版本按场景推**：标准色、反白、品牌色底、单色黑、单色白，每一个都对应一个真实场景；工艺版（压印、烫印等）只在这个品牌真会用到时做。
4. **辅助图形从母题的“关系”延展，不是复制标志的形**：把签名细节里的那个关系（例如“一点落在一圈的最低处”）变成版式规则、分隔方式或动效，而不是把标志缩小平铺成花纹。辅助图形服从标志，不与它抢主角；它具体怎么长、可以多显眼，按本风格 `style-extension.md`。
5. **动态的性格按本风格**（`style-extension.md`）：先写清楚动态在说什么（出现、思考、完成），终点帧必须就是标志本身；只做说这件事需要的动作。
6. **错误用法**：挑这个标志最容易被用错的方式（变形、旋转、改色、加效果、拆开组合、放错底色），每条配一张图。
7. **字体与色彩规范**：日常排版推荐可商用的中英文字体并注明授权；色彩给出色名、HEX、RGB、CMYK 参考值和用色比例（按本风格 `style-extension.md` 的色彩比例，写成具体百分比）。

| 项目 | 内容 |
|---|---|
| 组合方式 | 竖式（首选）、横式、单行、纯字标、纯图形（App 图标、头像） |
| 色彩版本 | 标准色、反白（深色底）、品牌色底、单色黑、单色白；按需要加压印 / 烫印等工艺版本 |
| 留白 | 四周最小留白，以基准尺寸表示（例如 0.5 D） |
| 最小尺寸 | 屏幕（px）与印刷（mm）各一个；需要时给出小尺寸专用版本 |
| 错误用法 | 至少 4 种，每种配图 |
| 动态 | 2–3 帧说明标志如何出现、如何表示状态（加载、完成）；可选 |
| 辅助图形 | 从母题的关系延展出的版式规则或图形；不能喧宾夺主 |
| 字体规范 | 标志用定制字；日常排版推荐可商用的中英文字体（注明授权） |
| 色彩规范 | 色名、HEX、RGB、CMYK 参考值、用色比例 |
| 构造图 | 规则的可视化说明 |

## 7 场景：怎么做与清单

**每个场景都要证明一件事。** 场景不是装饰，是让用户看到标志在真实使用里成立。挑场景时先问：这个场景证明了什么？证明不了新东西的，换掉。

| 场景 | 证明什么 |
|---|---|
| 名片 | 小尺寸与工艺（压印、烫印）是否成立；字与图的分寸 |
| App 图标 / 头像 | 16–48 px、圆形裁切下是否认得出 |
| 官网首屏 | 横式组合与版面节奏；动态状态 |
| 前台形象墙 / 门头 | 远看是否成立；大尺寸下的精度 |
| 提案封面 / PPT | 品牌色与版式；字与图的关系 |
| 包装、手提袋、周边 | 材料与色底版本；辅助图形是否和标志出自同一审美 |

**怎么做**：
1. **先列，再确认**：按行业和简报里的场景约束列出 6–10 个，请用户确认后再做。本风格 `style-extension.md` 写了最能证明本风格的场景和材料，优先从那里挑。
2. **用代码做扁平示意**：`scripts/mockup.py` 提供名片、App 图标、官网首屏、形象墙、提案封面、手提袋等模板，直接放入本项目的 SVG，比例按真实尺寸（例如名片 90 × 54 mm）。
3. **统一观看条件**：同一套场景用同一种底色、同一种光、同一个角度；不要一张写实、一张卡通。
4. **占位要诚实**：名片上的姓名、电话用占位条，不编造个人信息；工艺效果是模拟的，就标注“模拟”。
5. **不伪装成实拍**：扁平示意就说是示意。需要写实效果图时，请用户提供实拍底图或交给专业渲染，不用 AI 生成的“照片”冒充成品。
6. **每个场景配一句话**：说明它证明了什么。

| 类别 | 常见场景 |
|---|---|
| 办公 | 名片、信纸、信封、邮件签名、PPT 模板、工牌 |
| 数字 | 官网首页、App 图标、社交媒体与企业微信头像、产品界面（加载 / 完成状态）、网页 favicon |
| 空间 | 前台形象墙、导视、展台、门头 |
| 活动与周边 | 活动主视觉、海报、手提袋、包装、纪念品 |

B2B 科技公司默认优先：名片、官网、App 图标、企业微信头像、PPT 模板、前台形象墙、活动主视觉、产品界面状态。

## 8 提案：怎么讲与结构

**提案讲的是“对这个品牌的新认识”，不是“我们画了什么”。**

**怎么讲**：
1. **顺序**：先讲认识，再讲形——品牌本质 → 母题 → 形的事实 → 构造 → 体系 → 场景 → 风险与下一步。让对方先同意那个认识，形就水到渠成。
2. **一页一个想法**：标题就是这一页要对方记住的那句话。
3. **用证据，不用形容词**：构造图、小尺寸测试、审看板，比“简洁大气”有说服力。
4. **讲走过的路**：挑一两页展示被否的方向和为什么否，让对方看到判断，而不只是结果。
5. **提案本身就是本风格的作品**：版面、字、颜色、图片、叙事语气和页面节奏，按本风格 `style-extension.md` 的“提案”来；提案是标志的第一个场景。
6. **演讲备注**：每页 30–60 秒的口语稿，先说结论，再说理由；不念页面上的字。
7. **篇幅**：单方案 15–25 页，多方案 25–40 页；导出 PDF 与 PPTX。
8. **之后**：提案后收到的反馈，先查 `feedback-playbook.md` 判断该退回哪个阶段。

| 部分 | 内容 |
|---|---|
| 封面 | 品牌名、提案名、一句核心理念 |
| 品牌理解 | 名字拆解、业务与客户、品牌本质的新认识 |
| 设计思路 | 本风格的思想与方法（用本项目的话讲，不讲空话） |
| 核心概念 | 母题、矛盾、形的事实，一页一个想法 |
| 走过的路 | 一两页：被否的方向与原因 |
| 构成语言 | 图文同源的规则 |
| 每个方案 | 开篇 → 概念 → 构造 → 图文呼应 → 组合 → 变色 → 规范 → 动态 → 场景（2–3 页） |
| 对比 | 多方案时的对比表与推荐 |
| 色彩与字体规范 | 色值、比例、推荐排版字体 |
| 风险与下一步 | 查重结论、商标检索、字形精修、文件定稿、VI 手册 |
| 结束页 | 一句话收尾 |

不同 AI 工具做演示文稿的方式见 `adapters/`。

## 后期制作：文件、工艺与交接

定稿之后，要让标志能被印出来、刻出来、放进产品里。

**文件**：
- **矢量**：SVG（描边已转为填充路径、节点干净、没有隐藏图层）；印刷用 PDF（或 EPS / AI，按供应商要求）。
- **位图**：PNG 透明底，常用宽度与 @1x / @2x / @3x；社交头像（圆形裁切预览）。
- **图标**：App 图标 1024 px 主图，并按平台导出所需尺寸；favicon 16 / 32 / 48 px 与 ICO。
- **命名**：`<品牌>-<组合>-<色彩版本>.<格式>`，同一套命名贯穿全部文件。

**颜色与工艺**：
- **CMYK 与专色**：给出 CMYK 参考值和专色色号参考（例如 Pantone），并写明“需打样 / 对色卡确认”；屏幕色与印刷色不会完全一致。
- **工艺参数问供应商**：压印、烫印、UV、丝印、刺绣、激光雕刻都有最小线宽与最小间距。把标志里最细的线、最小的空写出来，交给供应商确认；不够时启用小尺寸版或工艺版。
- **材料打样**：重要的落地物（名片、门头、包装）先打样，看实物再定。

**交接**：
- **商标注册用稿**：黑白、无渐变、清晰的图形与文字稿，按代理要求分别准备。
- **VI 手册**：把体系规范排成一本手册（PDF），供以后的设计师和供应商使用。
- **源码与说明**：附全部生成代码和 README，写清楚改哪个数会改变什么、怎么重新导出。
